# R152 results — broader first-pass wave: 5 of 5 outcomes correct, one real defect (2026-10-26)

Prereg: docs/project/rounds/2026-10-26-R152-prereg.md. Five firewalled
testers on fresh code areas (gevent, kombu, huey), outcomes not
pre-known. Adjudication re-ran the one confirm (id reproduces),
re-read the claimed defect in the code, and spot-checked every
clean model's faithfulness, bounds, and falsifiability control.

## Per packet

- pkt-komburesource (kombu `Resource`): **confirmed real defect**
  (race, id `1be10d1a348b`, reproduced). With `limit=1`, two
  threads can both check out at once: `_add_when_empty` tests
  `len(self._dirty) >= limit` (resource.py:59) but `_dirty.add`
  happens later in `acquire` (line 99), with no lock in between —
  both threads pass the check, each creates and takes a resource,
  `Cardinality(dirty)=2 > 1`. Control (acquire atomic through the
  add) is TLC-clean; raised bound same verdict. Nothing about
  this was known to the adjudicator before the wave.
- pkt-kombuchan (kombu `ConnectionPool`): **TLC-clean** on
  `NoDoubleCheckout` (693 states; Limit-1 and bound+1 cfgs also
  clean; mutant violates). Consistent with the Resource finding:
  the pool can exceed its limit by creating fresh channels, but
  each channel still goes to exactly one holder — the defect is
  the limit, not double-checkout.
- pkt-geventsem (gevent `BoundedSemaphore(1)`): **TLC-clean**
  (192 states; raised bounds 936, clean). Over-release path is in
  the model (`ExtraRel`); the bound check holds it. Defect-
  injected control violates in 2 steps, so the clean is not
  vacuous.
- pkt-geventqueue (gevent `SimpleQueue` handoff): **TLC-clean**
  (68 states), mutant (dropped putter dequeue) violates
  `ExactlyOnce`. One engine boundary noted by the tester and
  verified in the record: hub steps stay capped at `uncertain`
  because "no execution context reaches
  `gevent.queue.SimpleQueue._unlock` in the static facts" — it is
  reached only as a callback handle passed to
  `hub.loop.run_callback`, which static reachability does not
  resolve. It did not affect this slice's verdict (no
  counterexample arose), but it would cap any hub-callback slice.
  Candidate gap, recorded here for owner direction; not filed.
- pkt-hueystorage (huey `MemoryStorage`): **TLC-clean** (45
  states; bound+1 probe 96, clean; mutant violates). The
  expected-clean discipline case behaved: no defect forced, the
  documented exclusion (unlocked `flush_queue` etc. outside the
  brief) is stated in the spec as an assumption.
